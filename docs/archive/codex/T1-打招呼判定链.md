# T1：打招呼判定链（HelloTalk 6.4.20）

结论：**每日打招呼次数由服务端/IM 业务层拦截**；客户端有免费体验卡和重复对象的 UI 门禁，但未发现“已发送次数 >= 10”的本地计数。

1. 入口（附近/推荐列表）
   - `defpackage/cs3.java:152-198` 绑定卡片按钮；Hi 点击进入 `cs3.q(hsp, …)`（`cs3.java:265-294`）。
   - `cs3.q` 先调用 `jtv.a.l.c(1, hsp, num)`；该回调为页面/UI 条件门禁，返回 true 即 `return`（`cs3.java:269-274`）。
   - 通过门禁后调用 `utc0.h.f().d2(userId, …)` 做陌生人/关系检查；`bs3.F0` 对陌生人显示 Toast 并以 `-1` 回调，不发送（对应 smali `smali_classes6/bs3.smali:166-224`）。

2. 实际发送链
   - `bs3.F0` 的正常分支取 `utc0.h.o()`，调用 `z2h.R0(context, targetUid, source, tab, algoTraceId, callback)`（`bs3.smali:322-346`）。
   - 实现类 `klz.R0` 创建 `IMNewStickerBean`：productId=1、imageId=11、helloMsg=1，然后调用 `mwg.c(..., "new_sticker", SessionType.C2cChat, …)`（`smali/klz.smali:2867-3002`）。这是 IM 消息发送，不是本地计数器。
   - `mwg.c` 把消息交给协程/IM service；`mwg.d` 最终调用 `IIMChatBaseService.w1(...)`（`smali_classes7/mwg.smali:534-803`、`:805-1103`）。

3. 服务端错误回传与超限 UI
   - 发送错误回调为 `b7z.onError(int code, String)`；当 `code == 0x12 (18)` 时显示 “used up Hi” 弹层，并把 code 原样传给上层 callback（`smali_classes7/b7z.smali:65-225`；另一分支同样处理 `:228-306`）。客户端没有在此处累加或比较 10。
   - `rdy.smali:2458-2460` 把服务端错误键 `Message exceeded the upper limit` 映射到文案资源，和 code=18 的发送错误路径吻合。

4. 客户端本地状态（不是每日配额）
   - `qtv.B/E` 读写 `say_hi_state_data<uid>`，保存已打招呼对象 map（`defpackage/qtv.java:73-97`）；用于去重/刷新。
   - `vev` 的 `have_say_hi` 和 `say_hi_in_exposure` 只表示某对象/曝光是否已打招呼（`defpackage/vev.java:17-73`）。
   - `qtv.D` 的 `nearby_free_report_once_<uid>` 是上报去重缓存（`defpackage/qtv.java:287-339`），不是发送配额。
   - 附近页 `bip.free_sayhi_times` 来自接口模型；`bip.e()` 仅判断该值是否大于 0（`defpackage/bip.java:32-35,56-74`）。`dfk.invokeSuspend` 据此展示体验卡/选择用户弹窗或旧弹窗（`smali_classes6/dfk.smali:648-901`），属于本地 UI 门禁，未发现日累计。

5. 判定与后续验证
   - 允许发送时客户端无本地“10 次”比较，直接进入 `R0 → mwg.c → IM service`；超限只在发送错误回调中出现，因此判定为**服务端计数/拦截**（高置信度）。
   - 备用机到位后可做最小验证：仅 patch `cs3.q`/`jtv` 门禁使其始终放行，连续发送第 11 个不同 UID；若仍收到 code=18/同一弹层，即可把服务端结论从静态证据升级为实验确认。
